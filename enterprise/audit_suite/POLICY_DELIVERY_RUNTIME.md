# Local policy distribution runtime

`company_policy_delivery_runtime` implements a bounded company-owned POL001 exercise. It copies actual canonical document bytes into private local mailbox files, reads and returns those exact bytes, and records separate explicitly simulated recipient assertions. It does not send messages, prove human receipt or understanding, accept a policy, appoint staff, or establish workforce-wide distribution. CompanyStore originals remain independent of audit artifacts and testing conclusions.

Initialize a new private runtime with `initialize(destination, repository=..., plan=..., documents=...)`. The plan contains exact `runtime_id`, `company`, `branch`, scoped `owner_id`, `cycle_id`, `declared_at`, `due_at`, explicit `recipients`, and `local_basis`. Recipients must be existing persona IDs; the local owner must match the recorded POL001 primary assignment. That assignment is a coordination route, not new policy approval or authentication of a human command issuer. The recipient denominator covers only the declared local inventory.

Each of one to four admitted documents has `id`, canonical repository `path`, exact `sha256`, and `source_metadata_lines`. These lines must occur exactly in the committed Markdown bytes. They preserve source assertions without interpreting them as new approval. Admission uses the maintained canonical-document allowlist, verifies committed bytes, and rechecks before publication. For the approved corporate document standard, retain its actual Standard ID, version, September 2 approval date, and APPROVED DESIGN STANDARD status; placeholders in its templates are not company addresses, officer appointments, or legal names. The runtime never synthesizes a source version or corporate approval.

`execute` takes `expected_runtime_sha256`, exact integer `expected_revision`, `command_id`, `actor_id`, `operation`, offset-qualified `event_at`, local `rationale`, and exact `parameters`. The result has `receipt`; READ_RETURN additionally has binary `content`. Supported operations:

- `DELIVER`: owner supplies `recipient_id` and exact native-six `document_pin`. The runtime actually writes and rereads the selected original in a generated command-owned private path. It records byte hash and file identity; it does not record human acknowledgment.
- `READ_RETURN`: the explicitly asserted simulated recipient supplies their own `recipient_id` and current `document_pin`. A current exact delivery must exist. The response includes the verified original bytes; the immutable receipt records the digest and a simulated-actor qualification. This proves a local API byte-return operation, not human attention.
- `RECIPIENT_ASSERTION`: the same simulated recipient supplies `recipient_id`, `document_pin`, exact current `read_command_id`, and bounded `statement`. This creates an authored simulation assertion; `human_acknowledgment` remains `NOT_ESTABLISHED`.
- `SELECT_DOCUMENT`: owner supplies `previous_document_pin` and another exact `document_pin` already admitted at initialization. This changes the local distribution selection. Old deliveries/read events/assertions remain historical, and do not satisfy the newly selected document's delivery/read requirements. It is not an amendment to canonical policy approval. A future source catalog requires a separate explicitly initialized runtime, not a fabricated revision.
- `LOCAL_WITHDRAW`: owner supplies current `document_pin`. This withdraws the local distribution pointer, preserves all originals and mailbox files, and blocks new reads/assertions and historical byte-return replay. It does not repeal the canonical policy or erase an already delivered copy. Existing CompanyStore source access is a separate authority boundary.
- `RECONCILE`: owner supplies an empty object. The resulting native observation compares the declared inventory to actual committed delivery/read/assertion history at the command time. It preserves missing due, prior-version-only, late, and withdrawn distinctions. It never produces a control pass.

All commands use local nondecreasing UTC-normalized event time and distinct actual import timestamps. `inspect(..., as_of=...)` is a read-only current-state report and rejects a cutoff before retained current state; it does not invent historical snapshots or execute the scheduled activity. Due comparisons are UTC instants: absent delivery is due at the declared instant; a delivery strictly after it is late. No daily schedule, external SLA, or 24x7 process is inferred.

Each write transaction reconstructs prior operations and validates exact native metadata, command receipts, state, code pins, document bytes, and retained mailbox device/inode/hash. Native operation, command receipt, and revision commit together. Historical exact command replay appends nothing; changed envelopes and stale revisions reject. READ_RETURN replay also checks current local withdrawal/version status before returning bytes. Maintenance source-file hashes identify source code, not a complete loaded-binary or OS attestation.

Mailbox publication has an explicit filesystem/database boundary. A no-follow anchored private directory and fsynced INTENT precede copied bytes. Files and directory entries are synced and reread before native commit. Failure after filesystem writes can leave a retained uncommitted attempt. Inspection labels it `UNCOMMITTED_ATTEMPT_NOT_DELIVERY`; no copy is silently adopted, removed, or treated as an acknowledgment. The same failed command cannot overwrite it. A new explicit command is required after inspection. Database replay only covers commands that actually committed. Retained file replacements fail even if their bytes match. The owner must keep the runtime directory private; these controls do not defend against a malicious process with the same operating-system identity.

SQL preflight bounds all native and runtime-state metadata before materialization and again before commit. Limits are four documents of at most 256 KiB, 32 recipients, 64 commands, 128 owned attempt directories, bounded receipts/state, and a 16 MiB aggregate table quota. Originals use `REPOSITORY_SYNTHETIC_DOCUMENT`; operation observations use `AUTHORED_TRAINING_SOURCE`. No grant, collection, model, or audit command is created.
