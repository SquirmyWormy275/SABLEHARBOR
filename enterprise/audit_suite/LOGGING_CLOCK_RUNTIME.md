# Local logging clock companion

`company_logging_clock_runtime.py` adds a prospective native source family for the clock-gap clause of SH-SEC-002. It does not change the historical paired security-log exercise. That exercise's `ingestion_lag_seconds` measures collector arrival after a source event and remains explicitly distinct from device clock offset.

A trusted local operator creates a fresh private `CompanyStore` runtime using an exact native logging inventory and a separately persisted local time-reference definition. The contract names one device and logging source, a distinct operating review contact from the pinned SH-SEC-002 assignment, a start/cadence/grace window, and a local offset threshold. The contract must predate its observation slots. Its reference has `LOCAL_REFERENCE_DECLARED_NOT_ENTERPRISE_TRUST`; the policy state remains `LOCAL_RULE_NOT_ACCEPTED_SECURITY_OPERATIONS_POLICY`. There is no accepted enterprise reference, threshold, cadence, deployed device, or approval in current canon.

For a slot, `record_clock_observation` reads exact version/hash-pinned native `device_clock_sample` and `time_reference_sample` bytes from their company source roots. Each sample binds the pinned inventory or reference definition, device/reference identity, slot, and shared capture identifier. The operation compares the two clock readings using exact signed integer microseconds, stores both that value and an exact fixed-decimal millisecond display value, and evaluates the local millisecond threshold without floating-point conversion. It also stores the attributed local alert state and `PENDING_NOT_PERFORMED` review state in a versioned `clock_observation` row. The shared capture identifier is a local fixture/adapter assertion, not independently certified simultaneity or reference trust. `record_missed_observation` records `NO_SAMPLE_SUBMITTED_BY_LOCAL_DEADLINE` after a slot's grace period, with null offset and an attributed local alert. It does not claim a sample was absent from the underlying device or reference. Both outcomes are ordinary collectable native company-source versions, and duplicate or conflicting writes follow CompanyStore's command and version checks.

Both native sample events must occur at or after the scheduled slot and no later than the recorded observation; a source that announces a future capture before its due time fails closed. The two sample bodies must name the exact scheduled capture time. This is a chronology check on the local source records, not a certification of the device's own clock.

This is a bounded local source capability. It does not establish enterprise clock synchronization, monitoring coverage, approved Security Operations policy, performed operating review, or SH-SEC-002 audit task credit. An actual company run requires an accepted reference and local authority for threshold/cadence, real device observation sources, and substantive collection/mapping review. The tests execute only on fresh isolated synthetic source/runtime roots; no A/B audit workrooms or existing company source roots are changed.
