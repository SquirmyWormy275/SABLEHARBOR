# Selected company-library security and continuity fieldwork

The standalone `source_library_security_execution.py` runner requires exact independently accepted company-library pins and the separately pinned root adapter review. That adapter review must use schema `SH_ROOT_SOURCE_LIBRARY_ADAPTER_INDEPENDENT_REVIEW_V2`, verdict `PASS_QUIESCENT_ENGINE_BOUND_ADAPTER`, `source_execution_authorized=true` and the exact installed adapter module hash. The runner does not issue its own acceptance. The instruction-only program pack is pinned independently.

Each opaque company branch receives a new ordinary-byte source copy before `Engine.create`, a unique new engagement and distinct company operator, auditor and reserved reviewer. Seven evidence/work collections start at zero. No previous mutable workroom is copied. The reference period is January 1–December 31, 2027 with January 3, 2028 fieldwork, SOC 2 Security/Availability/Confidentiality and the fictional HIPAA BA/subcontractor scenario. This is synthetic company history, not actual PHI or deployment. Both workrooms use the same ungenerated configuration; branch names do not determine conclusions.

Company business routing is read as native system metadata. Unregistered requested systems remain explicit scope gaps. After normal activation and kickoff, the source operator grants only declared registered systems for that branch. Three issued PBC requests route security/vulnerability/continuity originals to their relevant controls. Discovery is bound to the actual Engine clock; typed exact-version collection retains existing native bytes, receipt identities, provenance, availability and real import clocks. Grants are revoked after performance. The accepted source database and original frozen raw-source pilots are untouched. No transformation, private recipe, instructor Key or earlier audit observations are read.

The auditor seals business record locators and selection rules before outcome inspection. `source_library_security_methods.py` then performs three bounded examinations over the actually collected records:

- SEC003/CC7.1 reconciles selected inventory, baseline, schedule and scan asset IDs and count claims. It joins exact upstream projected references and traces a disclosed synthetic advisory through detection, triage, approval, remediation and retest. A missed finding on an observed EDGE asset remains distinct from an omitted OPS asset; no detection/parser cause is invented. Advisory availability is checked against the initial scan, and later company self-review remains visible.
- SEC005/TOE examines initial approval/baseline/application chronology and independently reconstructs native publisher records available at each collector/review snapshot. It compares publisher, received and reviewed IDs and required-agent coverage. Explicit local model qualifiers remain part of the result. It does not establish network traffic, executable enforcement, installation restrictions, CC6.6/CC6.8 closure or a SEC002 logging procedure. Later correction approvals cannot substitute for initial approvals; calendar-month tails remain outside snapshot conclusions.
- BCM003/A1.3 retains each selected exercise version, joins local BIA/technical-objective/authority originals and recomputes recorded start-to-finish duration against the documented local target. Company marker-digest/usability and replay-gap flags remain attributed claims. The historical marker original/backup bytes are absent, so isolated restore, recovered-data age, integrity and usability remain unperformed. Older real local backup originals are outside this source boundary and are not used as a fallback or replacement for the historical marker.

Supported engine commands create separate per-task populations, reliability decisions for the declared limited purpose, entire selected samples, a separate judgmental advisory trace, linked auditor workpapers, sampled-item observations and bounded findings. The three exact tasks remain `IN_PROGRESS/LIMITATION`. Other tasks stay not started/not run; corpus counts or source collection do not award their credit. The reserved reviewer performs no work on behalf of the auditor.

`--verify-only` performs a separate read-only inventory/pin check, native-history/schema comparison, actual audit command-chain verification, membership separation, exact retained-byte and collection-receipt checks, method reperformance and sample/workpaper lineage checks. This validates reproducibility of the selected documentary/model work. It does not establish independent professional or owner acceptance, evolving-source journeys or full enterprise/year operating effectiveness.

The CLI requires `--repository`, a new private `--destination`, `--source-pins`, `--program-pack`, `--adapter-review` and `--adapter-review-sha256`. Run the same command with `--verify-only` against the existing output for separate verification. Source pin JSON contains exactly the seven `AcceptedLibrary` dataclass fields: database/path hash, manifest/path hash, review/path hash and positive version count. All output directories are 0700 and files are ordinary single-link 0600 bytes. Candidate pins and exact commands belong in the private handoff after execution; output history is never overwritten on retry.

Meaningful neutral tests cover the omitted/observed advisory discrepancy, advisory timing, changed upstream/prior digests, collector population omissions, late correction approvals, missing model qualifiers, exact continuity versions and recorded-duration contradictions without restore credit. Adapter isolation/clock/WAL tests remain separate. Actual accepted-company runs must follow those engineering checks and the independent source/adapter gates.
