# Explicit investigation handoffs

`InvestigationHandoffs(private_root, engine, max_active=16)` stores personal coordination in a separate private `handoffs.sqlite3`. It never changes formal audit tasks, control conclusions, workpapers, assignments, source grants, review acceptance or model context. `COMPLETED` means the named recipient supplied a coordination response; it is not an independent review or control-completion statement.

The caller supplies an existing owned 0700 directory; the database is 0600 and cannot be a symlink or hardlink. Immutable version documents retain the original sender, recipient, question, next step, exact references and participant context pins. Each action adds a version with its author, timestamp, engagement revision, previous document hash and immutable command receipt. No private investigation, draft, Key or source content is imported automatically.

## Methods and bounds

- `directory(actor, engagement)` returns `engagement_id`, `engagement_revision`, and `members` containing only active current auditor-principal `id`, `display_name` and engagement `permission`. Company personas and credentials are not directory results; self is omitted.
- `make_reference(actor, engagement, recipient_id=..., kind=..., record_id=..., version=...)` returns an exact `{kind,id,version,sha256}` only when both participants' authorized Engine projections resolve it. Supported kinds are control, task, artifact, population, selection and workpaper. Workpapers require the selected historical version. Artifacts must be available; excluded procedures, duplicate identities and stale pins are rejected. No native source access is granted.
- `offer(actor, engagement, payload, expected_engagement_revision=..., command_id=...)` requires exactly `{recipient_id,title,question,next_step,links}`. Title/question/next step are explicit nonempty authored text, bounded to 120/2000/1000 characters. Links are an explicit list of at most 8 exact references; zero links is permitted for a standalone authored question.
- `read(actor, engagement, id)` and `listing(actor, engagement)` expose only participant handoffs, under current authorization. Listing returns a list for a route to wrap.
- `transition(actor, engagement, id, action=..., response=..., expected_version=..., expected_engagement_revision=..., command_id=...)` requires exact current handoff-version CAS and current engagement revision. Responses are at most 4000 characters; COMPLETE requires a nonempty response.

Only the recipient can ACCEPT or DECLINE an OFFERED item. Only the sender can WITHDRAW an OFFERED item. Only the recipient can COMPLETE an ACCEPTED item. Terminal states cannot be reopened or silently reassigned; a newly reviewed offer requires an explicit new command. Each participant has at most 64 lifetime handoffs in an engagement and a configurable 1–32 active limit (default 16). The private store is limited to 4096 documents and 64 MiB, with 32 KiB per document. The directory is limited to 200 members and listing to 128 items.

All mutations use one private database transaction and retain exact command fingerprints. Reusing a command with changed input conflicts. Exact replay returns the **current authorized projection**, not the historical response text, so a formerly successful request cannot reveal old shared text after revocation or context change. No claim is made that the private sidecar and audit store form one global atomic transaction; current authority and context are rechecked before returning or publishing.

## Shared visibility and disposal

Each participant has a separately pinned scope/company-binding/evidence-acquisition/membership basis. OFFER, ACCEPT and COMPLETE require both participants to remain authorized with matching bases and every selected reference available exactly to both. Reads redact the entire shared content when either participant is unavailable, a basis differs, or a selected target is unavailable. They never substitute a later workpaper version or create missing source access.

The acting currently authorized recipient may still DECLINE an unavailable OFFERED item; the acting currently authorized sender may WITHDRAW it. These disposal actions require ownership and exact CAS but do not require a currently available counterpart or reference. An expired or revoked acting principal cannot read, act or replay. Basis equality and reference availability are evaluated for each call; no historical authorization grants are recreated. A later engagement revision alone does not invalidate unchanged references, but action requests must explicitly name the current revision.

The response contains id/version/status, engagement and participant IDs, saved/current engagement revisions, author/timestamp, acting role, context status, shared-content visibility and allowed actions. `content` appears only when available and contains title/question/next step/links plus the current authored response and its author. `coordination_only:true` and `formal_work_mutated:false` always distinguish this workflow from audit work. Original and intervening responses remain in immutable private version history even when the latest projection is redacted.

## Inert recovery boundary

`snapshot()` is a trusted local operator method, not an unauthenticated HTTP read. It captures a consistent logical `{format,documents,commands}` archive under a read transaction. `validate_snapshot(body)` validates the exact bounded schema, each document hash, contiguous per-handoff chain, original user/participant/basis preservation, permitted author/state transitions and command-document associations. Command digests are retained associations; the validator does not reconstruct absent request envelopes or attest loaded binaries.

Explicit `companion_recovery.backup(destination, investigation_handoffs=handoffs)` includes a validated, hash-pinned private snapshot. Restoration retains `investigation-handoffs-ARCHIVE-ONLY.json`; it does not create a live handoff database, remap participants, grant access or resume offers. Existing engagement backups and older companion bundles do not automatically include handoffs. Support does not assert that a particular workspace has already been backed up. The snapshot contains private authored questions and responses, including historical text; retain it only in private bounded storage. Integrity validation is not professional assurance or protection against an operator replacing the entire trusted archive and all external pins.

Focused tests use disposable Engine actors and stores, covering recipient isolation, exact historical references, shared visibility intersection, CAS/retry, stale disposal, expired counterpart, revoked actor/replay, final authorization rollback, strict reference types, quotas, private paths and malformed inert archives. No actual offers or live workspace mutations were performed.

The loopback workspace exposes capability-gated `/api/engagements/{id}/handoffs` routes for the participant list, exact-link selection, offers and explicit transitions. Cookie mutations require CSRF protection. The browser preserves authored text after a conflict, requires review of updated context, and retries ambiguous transport failures with the exact original command. Content is rechecked on refresh and actions; this is not a push revocation service and does not erase information already read.
