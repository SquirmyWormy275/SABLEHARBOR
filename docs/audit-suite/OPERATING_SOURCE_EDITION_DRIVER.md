# Separate modeled source edition

`company_operating_source_edition.preview(plan_pin, admission_pin, repository=...)`
reads externally SHA-pinned private JSON and the named canonical organization.
It does not open company or audit databases. `execute(..., destination=...)`
creates or resumes a new private edition only after that preview. Neither API
creates an audit, reads workpapers or a Key, imports procedure outcomes, nor
grants source access. A machine-pinned Root admission is required for actual
execution. The OWN admission class is engineering only.

The selected concrete source plan remains the original f754b0af file. A caller
supplies a finite explicit program and exact original native pins; the driver
does not select an estate, invent account populations, infer dates, or expand
the four admitted source-operation families into 70 controls or 409 procedures.
The activation API preserves every seed system/version field, including old
import time and exact bytes. New records have actual import/registration time
and an explicit simulated operation clock. These are different clocks.

## Input contract

Both arguments are exactly `{path, sha256}`. The plan schema is
`SH_EXPLICIT_FICTIONAL_OPERATING_SOURCE_EDITION_PLAN_V1`, with exactly:
`schema, edition_id, qualification, capsule, concrete_plan, modes, program,
finish_at, fresh_audit_not_before, source_unknowns`.

Each mode contains exactly `mode, company, branch, retained_period_refs,
original_input_refs, historical_unperformed`. All 36 retained joins are explicit
original pins: 12 denominator snapshots, 12 monthly reconciliations and four
each quarterly population, decision and followup. A historical limitation has
`id, reason, source_refs`; its references must be in the admitted original vector.
The original source capsule is independently pinned and activated normally.

A program step is exactly `id, mode, action, at, arguments, source_refs`.
Arguments are checked against the finite existing API registry, including exact
backup/restore wrapper argument contracts. Paths are explicit edition locations
(`company`, `ledger:<earlier step>`, `runtime:<earlier initializer>`), never
caller-supplied external runtime roots. Earlier same-branch result pointers are
`{"$result":{"step":"ID","fields":["native_pin"]}}`, at most four fields.
Literal native inputs must appear in both the step vector and mode admission.

The admission schema is `SH_ROOT_OPERATING_SOURCE_EDITION_ADMISSION_V1`, with
exactly `schema, status, plan, capsule, concrete_plan, code_pins, source_review,
original_edition_preserved, current_pipeline_complete, actual_execution`.
`ROOT_APPROVED_SEPARATE_SOURCE_EDITION` requires the last three booleans true.
The separate OWN class requires `actual_execution=false`. External admission
is supplied by the trusted local operator; the driver never manufactures it.
`source_review` is an external pin declaring source-only admission, the exact
capsule and native-field preservation. Unknown/unfilled inputs fail closed.

## Chronology and finite program

An independent native `business_inventory` calendar must precede operations.
New declaration registration is physically `operating_depth_definition` and its
record equals its runtime ID; a same-byte unrelated role/record is refused.
Inventory is not inferred from `account_system_inventory`. Commissioning is
only `site_release` or `transition.site_release`; local service criteria are
only `service_criterion`. Generic exact exclusion decision references remain
distinct from these role admissions.

Prospective registration may contain only then-available retained joins, even
zero. The December/Q4 originals available January 1, 2028 remain late-available
originals. A later registration version binds all 36 at its actual modeled date;
it does not move their clocks or declare a December completion. Actual cadence
and prospective due slots determine lateness. CLEAN does not require ceremonial
removals; MESSY P014 omissions and unperformed P015 requests remain historical
source limitations. A later real local removal cannot invent an earlier one.

November policy operations copy exact already-native document bytes. Delivery
and parsed read are separate source operations, not human acknowledgment. The
actual filled plan must retain the named eight recipient scope; the OWN proof
uses two recipients solely to verify mechanics. Retry re-performance consumes
the retained corrected config/build/test; it does not author another correction.

The normal prospective period API requires a new empty ledger, so the driver
creates `ledgers/<step>` separately from the activated seed. Backup initialization
binds that exact ledger through the existing API. Original R1/R2 remain historical
predecessor experiments. New commissioned copy/restore/use/failure operations
have their own prospective due slots, criterion and use contract; they cannot
retroactively cure R1/R2. A contract and local criterion precede actual new use.

Each source command is normal and idempotent. A missing checkpoint after a
commit causes fresh normal replay, exact current configuration validation and
result comparison, not outcome import. Receipts are O_EXCL/fsynced; failures
preserve earlier operations and a new failure receipt. The original seed is
freshly compared to the externally pinned capsule before resume and closure.
Plan/helper/canon changes refuse. The source edition must finish before any
fresh audit birth, which may legitimately be after January 2028 while assessing
the approved 2027 period.

## Ordinary discovery and collection boundary

The completion receipt declares separate typed physical source roots, database
SHA/bytes/seven identities, exact registered-system/owner tuples, native version
counts and zero audit-authority counts. Each root can be used by the existing
`CompanyStore.discover/read_version/collect` APIs with a later explicit grant.
New definition and inventory/criterion emissions include truthful JSON filenames
so ordinary typed retained-input decoding can consume their genuine originals.

These roots are not yet one `PersistentCompany` source. That existing API accepts
one independently admitted CompanyStore. A separate lossless source-edition
publisher/admission must compare every native system/version row and preserve
all old and new headers/bytes/input digests. It must reject any system owner,
native record/version or command conflict; no aliasing or retimestamping is
authorized. No collisions are asserted merely from generic family names:
policy uses `policy_definition`, backup uses `runtime_definition`, and period
declarations use `operating_period_ledger`. Root owns the separate publisher.
Completion explicitly marks this federation/new-audit admission as required.

The completed OWN fixture contains all four relevant source mechanisms but
does not establish actual 5608-source preservation, whole enterprise scope,
human review, professional acceptance or current audit acceptance. The selected
historical source plan, source unknowns and historical omissions remain explicit.
