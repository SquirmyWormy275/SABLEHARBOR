# Reporting method

All reports read posted journals or run-owned database domain records through an explicit compatible
generation-run context. The named SQL registry covers ledger, source trace, software/customer,
workforce/vendor, AR/AP exposure, assets, Red Wash, BS&T railway, Cradle, intercompany, debt, scenario,
assumption, and release-coverage views. The AR/AP view is an exposure reconciliation: only AR has
due-date buckets, AP due dates are unavailable, and disclosed non-document source-event exposure
bridges the document population to the GL.

The six-workbook suite is generated only after enterprise financial validation passes for the
selected completed run. Exact sheet specifications route each sheet to a named query, a monthly
statement report, or an explicit limitation/empty state. Workbook formulas provide visible local
controls, and Check sheets also reproduce the database validation registry; no workbook is the sole
source of a fact. The structural test contract reopens generated files and inspects required tabs,
formulas, broken references, external links, and practical size.

Generated 2023–2026 values are synthetic scenario/calibration records. August 31, 2026 is emitted as
`synthetic_calibration_through`, never as a report knowledge cutoff. Current outputs use
`RETROSPECTIVE_CURRENT_CANON`, record canon effective through September 3 and reconciled/prepared
September 5 from `CANON_SOURCE_LOCK.json`, and carry content-addressed generator/input/source
metadata. Report titles, calibration boundaries, and technical reconciliation controls do not
assert observed company results, historical books, or audited statements.

The current cash-flow workbook surface is a simplified cash-movement bridge. Full classified cash
flow, tax, valuation, purchase-price-allocation, and advanced consolidated reporting marts remain
limited as documented.
