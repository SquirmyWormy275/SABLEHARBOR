# Native operating-depth physical input roles

This successor changes only input admission in `_validated_definition` and
`restore_return`. APIs, native record schemas, existing versions, fictional
clocks, and the original policy/IAM/retry/restore/period behavior stay intact.

| Input | Admitted literal system roles | Continuing requirements |
| --- | --- | --- |
| Independent operating calendar | `business_inventory` | Exact six-field pin, independent calendar, full system coverage or explicit exclusions, same company/branch, bytes and source clocks |
| Existing commissioned release | `site_release`, `transition.site_release` | Exact pin, existing bounded release status, simulated operating release declaration, actual window and source clocks |
| Local restore-return criterion | `service_criterion` | Exact pin, complete local criterion schema, distinct actors, prospective approval, genuine copy/restore/read and local capacity checks |

The retained `person-access-history.account_system_inventory` supplies existing
person/account context. It is not an operating-calendar alias. Even identical
calendar bytes under that role are refused. `bcm.business_impact` and
`bcm.technical_objectives` are not local service-return criterion roles. An
invented family prefix does not grant any of these three roles.

Explicit `exclusions[].source_ref` remains a generic exact same-scope native
supporting decision reference. Such decisions may originate in different native
families; they do not replace inventory, release, or criterion inputs.

The literal release family is established by the original concrete edition plan
(`transition.site_release/RL-RENO` and `transition.site_release/RL-BOISE`). Local
fixtures use `site_release`; their independent calendar and new local criterion
are `business_inventory` and `service_criterion`. This does not assert that an
actual account inventory already contains the newly declared calendar.

Focused OWN tests append exact equal-body native records under the known and
wrong roles before invocation. Admission and registration refusals preserve all
native tables. Criterion refusal follows real local copy/restore/use-probe input
preparation and preserves the business records. These are fictional mechanism
tests, not actual source, whole-estate, audit, or professional acceptance.

The original cb5 worktree, handoff and independent rejection remain unchanged.
An intermediate broader inventory set and the first test-wrapper failure are
preserved privately; neither is the selected source. Actual source editions,
collection, method reperformance, Key binding and adoption remain separate.
