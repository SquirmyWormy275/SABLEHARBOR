The Markdown files in this folder supply the Wiki's articles and navigation. ## Publication status

The [live GitHub Wiki](https://github.com/SquirmyWormy275/SABLEHARBOR/wiki) is published. Its first 56-page edition was accepted in September 2026. [PR #155](https://github.com/SquirmyWormy275/SABLEHARBOR/pull/155) added fuller business, department, and history articles, along with 198 complete supporting records. Earlier reports that the Wiki was unavailable describe the situation before publication.

The live Wiki's `sable-harbor-wiki-manifest.json` records what was published: the source revision, page hashes, and input files. The [publication freshness workflow](../../.github/workflows/wiki-freshness.yml) checks those inputs and the remote pages after changes to main and once a day. It flags stale pages, edits made directly to the Wiki, and failures to inspect the publication. It does not publish changes.

To publish an update, use `make wiki-publish` from a clean, refreshed checkout of accepted main, with existing local Git authentication. The optional [manual Actions workflow](../../.github/workflows/publish-wiki.yml) needs its own configured `WIKI_TOKEN`. Local publication does not require copying a personal token into repository secrets.

Edit the repository sources, not the live Wiki. The [Wiki policy](../governance/PUBLIC_REPOSITORY_AND_WIKI_POLICY.md) explains which records are authoritative. Older page addresses still lead to the renamed pages, including their original section links.

## Maintenance and review

Business and department pages introduce their subjects, suggest what to read, and identify unanswered questions. The exporter adds their selected source documents to the in-depth reading sections. Change facts in the original records, rather than writing a competing version into a guide.

The [library](Library.md) and `library/` pages are generated by `tools/documents/build_institutional_catalog.py`. That tool also updates the reader discovery tables in the institutional SQLite catalog. Regenerate those indexes; do not hand-edit them.

These pages reuse approved artwork and charts without changing them. New visual designs still require the owner's review of small batches of exact files. The [reader delivery record](../reader/READER_DELIVERY.md) describes what was included and how it was checked.

## Review locally

For a GitHub-like browser preview of the Markdown and existing images:

```bash
python -m pip install -r tools/documents/reader-preview-requirements.txt
python tools/documents/preview_reader.py
```

Open `http://127.0.0.1:8765/README.md` to browse the repository Markdown. To inspect the complete reading edition and its older page addresses, follow the export and browser commands in the [publication guide](../../tools/wiki/README.md). The preview runs only on your machine and does not publish anything. GitHub's final layout may differ. Stop the preview with Ctrl+C.

The [automated browser review](../../tools/ci/README.md#wiki-browser-review) checks department and business headers in light and dark themes at mobile and desktop widths. It also checks that the approved headers have not changed. Review screenshots are not replacements for the approved artwork.
