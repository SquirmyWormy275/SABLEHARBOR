## Acceptance and limitations

The release receipt must identify the exact merge, not an unmerged candidate or an
unrelated later main revision. The package builder verifies actual PR acceptance
and the hash-bound scope in the register. This adopts only the stated company
source successor; preserved draft terms, future duties, control failures and
external deployment dependencies retain their own states.

Company financial presentation uses the declared synthetic management accrual basis.
The edition is not a US GAAP assertion, audit opinion, actual tax filing or proof of
solvency. The portal is a separately owned active workstream. Its committed software
can be exercised in isolation without asserting that every runtime capability or
external deployment gate passed. A residual affecting a requested inspection claim
must be carried explicitly in the receipt; packaging does not erase it.

Historical finance releases, approved artwork and the delivery policy's inventoried
ZIP exceptions retain their original bytes and identities. A correction to this
published version requires a separately versioned successor, never replacement of
an existing release asset under the same name.
