# Incident and continuity activity slice

`company_incident_activity.IncidentRecipe` / `generate_incident` builds one incident before any audit, using a dedicated company store and explicit paired branches. It reuses the canonical `SVC-compute` service and the approved corporate reference geography: `RUNTIME-RENO-COLO` / `FAC-PRIMARY` / `SH-SITE-0028`, and `RUNTIME-BOISE-DR` / `FAC-RECOVERY` / `SH-SITE-0029`.

The controlling runtime decision and structured site source distinguish provider selection from contracts, installed equipment and operation. Every incident source repeats the retained sites' provider-selected, non-operating qualifiers and identifies its activity as an isolated reference exercise. The local probe endpoints, credential reference, severity threshold, escalation deadline and recovery criteria are fictional branch assumptions. They do not create accepted corporate policy, a contractual SLA, a deployment, a new personnel appointment or PHI/ePHI activity.

The procedural anchors are SH-INC-001 severity/commander/escalation; SH-INC-002 chronology and communications; SH-INC-003 contributing-factor review and preventive actions; and SH-INC-004 accountable, dated actions with validation evidence. Current scoped engineering/incident contacts act as responder and commander; the assigned operating reviewer is outside their recorded response execution. This is an identity and activity separation, not a professional qualification claim, and does not assign Internal Audit an operating task.

Both branches retain matching system inventories and identical initial inventory, monitoring and ticket sources. In one branch, the first dispatch remains queued and a later retry delivers it. Commander acknowledgment gates recovery authorization. The delay therefore propagates into the recovery, monitoring, status and case records. In the current March 2027 recipe, restoration is observed 24 minutes after discovery in one branch and 54 minutes after discovery in the other. These are calculated fictional timestamps, not a performance benchmark or an effectiveness judgment.

A separate timed dispatch replay supports the subsequent corrective-action validation. Original escalation, incident and recovery versions remain retained after the preventive action closes. The outage's underlying technical cause remains explicitly unestablished: monitoring failures and response delays do not diagnose it. The postincident record requests further diagnostics rather than inventing a root cause.

The current private run is `enterprise/generated/audit-suite/company-incident-period-2026-09-14/v2/`, containing the company database, recipe, exact source/code pins, receipts, summary and focused test report. It has 36 source versions across ten systems per branch. Source hashes, referenced source versions, chronology, repeated-import identity and future-source denial are checked. No audit or access grant is created by the generator. The preceding run and its matching source module are preserved; v2 incorporates a source-format-only cleanup and has its own exact pins.

The tests exercise this bounded generator and store, not an external assessment. Production recovery acceptance, real independence, legal/contractual notices, regulated-data assessment, full corporate incident populations, retention and complete continuity testing remain outside this slice. Existing identity/mover stores, explanation snapshots and live walkthrough stores are unchanged.

## Isolated audit collection verification

The paired Engine collection exercise creates two new audit engagements scoped to SH-INC-001 through SH-INC-004 with the same corporate boundary and March 2027 dates. It activates the company-source connection, starts kickoff, creates and issues four scoped PBC requests, advances the clock, discovers source records, and collects all original versions explicitly. Source generation is absent from that audit path: the private run consumes the previously created v2 company store.

Each engagement retains 18 original source versions. The exercise checks every audit artifact against the preexisting source-version hash, verifies the audit history, and confirms that no generated world exists. Before incident availability, discovery returns no escalation records and exact future-version collection is denied. Revoking the isolated actor's source grant denies both discovery and collection. Test grants are revoked in cleanup. These permission-journal changes do not alter the original source versions.

Private audit states, code/program-pack pins, comparison receipts and the focused integration-test report are under `enterprise/generated/audit-suite/company-incident-period-2026-09-14/v2/collection-v1/`. The 24-minute versus 54-minute comparison reads the collected recovery records; it does not create a finding, complete a testing task, grade an engagement or approve professional sufficiency. This verifies the Engine command path, not browser interactions or company-model dialogue. The live service is unchanged.
