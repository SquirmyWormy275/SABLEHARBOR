# Identity period slice and remaining coverage

`company_activity_period.PeriodRecipe` / `generate_period` composes explicit, distinct-employee mover causes before an audit. It uses a dedicated company store and matching branch inventories. It stages and validates the complete recipe before target-source writes, retains exact source versions and hashes, and rejects unrelated preexisting records. Replaying an unchanged recipe preserves its original receipts.

SH-IAM-003 is event-driven: compare old/new required rights, remove obsolete entitlements and reconcile applications/site access. SH-IAM-004 is also event-driven: at an authorized termination/expiry, disable accounts, sessions, tokens, remote access and physical credentials, reconcile connected systems and escalate omissions. Neither requirement is replaced with a quarterly cadence. SH-IAM-007 separately requires quarterly review of privileged access and a risk-approved cadence for other rights. This implementation's quarterly records apply only to explicitly classified fictional privileged application rights; it does not invent an approved cadence for ordinary rights.

The current private exercise covers two employees and Q1/Q2 2027. Each mover produces linked HR, directory, application, site-access and operational-review versions. Each quarter closes before its population export, owner decisions and reconciliation become available. The second quarter retains earlier visible accounts; it is not merely a list of that quarter's changes. Population members pin exact application record versions and hashes. HR reconciliation uses a separately enumerated HR source population. In the Messy branch an explicit query exclusion omits an actual employee, while the underlying source records remain. The operational reconciler requests a new export. Retained obsolete application rights remain visible in source records; review instructions never fabricate completed removal confirmations.

The bounded inventory is the accounts established by the declared mover causes in one directory, one application and one site-access system, plus the linked operational registers. Canonical employee identifiers and current source/control pins are reused. Local roles, entitlements and transfers are expressly fictional scenario assumptions, and scoped operational contacts retain their existing provisional status. No accepted personnel or appointment record is amended.

Private recipe, source store, exact receipts and validation outputs: `enterprise/generated/audit-suite/company-identity-period-2026-09-14/`. Existing mover source stores, bound explanations and live v1/v2 walkthrough stores are preserved. No audit, source grants or hidden grading records are created by the generator.

Remaining gaps include termination/expiry, session/token/remote-access removal, independent removal confirmations, complete corporate account/system populations, approved ordinary-rights review cadence and retention expiry. In particular, this module does not claim an expired artifact is unavailable while retaining an unrestricted readable original: retention enforcement requires a separate source-access contract. Existing immutable source versions remain retained. No whole-control effectiveness, professional sufficiency or grading calibration is asserted.
