# Optional IAM007 native review reconciliation

The existing trusted source reconciliation plan accepts an optional `iam_review_contracts` list of at most eight entries. Each entry contains `population_ref_id`, `decisions_ref_id`, `reconciliation_ref_id`, `application_ref_ids` and `hr_ref_ids`; every ID must already be in the plan's existing 64-reference budget. An omitted key retains the previous report shape. There is no discovery, new endpoint, source mutation, population import or audit command.

`iam_review_reconciliation.checks` adds a mechanical report section. It checks same routed component/company/branch, native IAM007 systems/control/quarter/boundary, strict UTC exclusive application cutoff, exact positive integer versions and 64-character SHA256 values. Duplicate member/decision/reference identities and repeated support IDs fail closed. Review sources cannot be available before their declared quarter cutoff.

The report compares the exact encoded native members list with `membership_sha256`, and both recorded `population_sha256` values with the selected original population hash. Decisions are matched by person, record, version and SHA to exact members. Member references can be checked against explicitly selected application originals for identity, rights, cause and availability before cutoff. Exact rights arrays remain visible; array order equality and permission-set equality are separate, so a reordered array alone is not treated as failed access control.

HR references resolve only to expressly selected HR originals. The report separates recorded HR/export/missing-person lists, recomputed differences between those recorded lists, and differences derived from all listed HR references when resolved. Any missing, mismatched or late HR source makes the latter comparison partial. “All listed HR references resolved” means precisely that; it never means all company people or accounts were selected. Latest-version completeness and enterprise inventory completeness remain unestablished.

Recorded authorization, decision and removal-confirmation text remain source assertions. Subtracting recorded authorized rights from observed rights tests arithmetic, not whether the authority was valid. `removal_execution` is always `NOT_VERIFIED`: a removal decision or a matching list does not prove implementation. These observations never accept a population, award testing credit, infer reviewer qualification or establish control effectiveness.

Validation: 42 combined focused tests passed, followed by three added passing regressions for omitted-key compatibility, native cross-boundary mismatch and review event/availability distinction (45 total covered tests). Cases include malformed boolean/float versions, hash mismatches, rights-array ordering, unresolved HR support, source cutoff, branch/quarter mismatches, duplicate identities and recorded/source-derived set differences. The existing registry/grant/revision and private-publication checks remain in the parent reconciler. Ruff passed.

Actual current evidence is the new private `reference-v4/dependency-period-v6/` report, `DEPENDENCY_PERIOD_PLAN_V6.json`, `DEPENDENCY_PERIOD_RECEIPT_V6.json` and `DEPENDENCY_PERIOD_VALIDATION_V6.json` beneath `enterprise/generated/audit-suite/company-portfolio-2026-09-14/`. It selects 34 originals: the prior 24 plus four application and six HR versions reused across quarterly contracts. All four native membership hashes and eight population-reference hashes match. The quarterly source-derived missing-person sets match the recorded sets, while later-quarter removal confirmations remain recorded as not yet performed. The declared inventory still contains only P014/P015. Original source versions and audit state are unchanged; prior outputs, including pre-boundary-check v4, remain historical.

A full company year is still **NOT_ESTABLISHED**. This extension exposes the difference between internally consistent records and complete, effective operation; it does not close that difference through labels or counts.

Review-event timestamps are reported separately from availability: UNDATED, EVENT_BEFORE_DECLARED_CUTOFF or AT_OR_AFTER_DECLARED_CUTOFF. Later ingestion never establishes when review occurred. Earlier v5 predates this explicit event-time observation and remains historical.
