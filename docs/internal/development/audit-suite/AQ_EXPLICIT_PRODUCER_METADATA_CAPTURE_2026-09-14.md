# Explicit producer metadata capture

`enterprise.audit_suite.company_activity_source_capture.capture_source` is a read-only prerequisite for an explicitly opted-in linked-plan consumer. Existing V2 bindings remain strict caller-predeclared metadata bindings and are unchanged.

The caller supplies `source_root`, `source_manifest_path`, `expected_manifest_sha256`, `source_store_id`, `expected_records`, `consumed_at`, and the actual consumer `destination`. Each of the two to eight selected references must contain exact company, branch, system, record, positive integer version and content SHA256. Missing hashes are rejected; the helper never discovers a latest record or chooses content. The producer label is an explicit caller label, not authentication of a native producer identity.

After verifying the completed company-only operator manifest and every pinned member, the helper reads precisely those references and captures their selected metadata digest once. It passes that frozen digest to the existing strict resolver, which independently rereads the selection and rechecks the producer manifest before and after its read. A changed pin fails rather than triggering another capture. The helper returns typed source references, `source_versions_sha256`, and a receipt tagged `CAPTURED_AFTER_VERIFIED_PRODUCER_NOT_CALLER_PREDECLARED`. The receipt separately states that content pins were caller-predeclared and the selected metadata pin was not.

Selected metadata contains the six native identity fields plus `event_at`, `available_at`, `origin` and `provenance`. It excludes content bytes and does **not** include `imported_at`. A provenance source revision can change while content bytes remain identical; explicit capture records that distinction without claiming the caller predicted the resulting metadata.

The caller remains responsible for validating the dependency DAG, restricting capture to a newly completed declared producer, retaining the original and resolved recipes and this receipt, and running later strict checks against the captured pin. The helper itself cannot establish that a producer belongs to a particular run. Only genuine operator manifests are accepted. There is no cross-job atomic transaction or producer signature authentication.

All source/member paths must meet the existing private, canonical, nonalias checks. The consumer destination must neither contain nor be contained by the producer job directory: a consumer sibling under the plan's jobs directory is appropriate; the enclosing plan directory is not. Selected event and availability instants must be known and no later than the explicit consumer cutoff. Both future evidence and unknown occurrence times fail this prerequisite. The helper creates no files, source records, grants, audits, or model calls, and establishes no coherent company year or control effectiveness.

Focused validation uses an actual maintained mover producer. Thirteen tests cover exact pins, unchanged original bytes, explicit label semantics, honest metadata fields, missing/wrong content pins, typed versions, duplicate references, cutoff, alias and containment rejection, a changed metadata pin between capture and strict reread, and producer manifest changes both after capture and during the final strict read. These are mechanical prerequisite checks, not professional source sufficiency review.
