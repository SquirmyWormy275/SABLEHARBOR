# Fresh identity family fieldwork

`enterprise.audit_suite.fresh_identity_family_procedure` performs a new paired
identity/access audit directly against isolated ordinary-byte copies of nine
company-owned native systems. Each engagement starts with zero workroom evidence.
Existing source journals remain opaque integrity inputs; existing audit results,
evidence and scenario keys do not transfer. The historical 236-instance index
supplies authored task membership only and is not a workforce count.

The exact selected vector is in `fresh_identity_family_spec_v1.json`: 30 authored
tasks across SH-IAM-001 through SH-IAM-007. Physical-access CC6.4 stays unstarted.
Both profiles use the same vector, whole visible component histories, exact cited
upstream joins and per-item test depth. Company discovery, source grants,
collection, populations, entire selections, workpapers, samples, inspections and
task dispositions use the existing supported APIs.

Fieldwork starts at the frozen 2027-12-31 09:00 UTC clock. Initial discovery proves
that Q4 review support is unavailable. An ordinary authorized `clock.advance`
then reaches 2028-01-15 09:00 UTC, without changing the 2027 engagement period.
Post-period review records support the Q4 due window; they are not presented as
in-period activity. All four due windows are reconciled against actual members
and application versions rather than claimed population counts.

The current histories establish two canonical mover subjects and independent
synthetic contractor, service and local-object cohorts. They do not establish a
52-person enterprise identity census or histories for the 15 proposed contacts.
The procedure preserves original misses after correction, unresolved upstream
joins, review objectivity gaps and raw-object parser quarantine. Native byte and
permission checks do not make quarantined objects available learner evidence.

Completed source examinations can conclude FAIL or LIMITATION. Broader clauses
remain IN_PROGRESS when population or other substantive procedure coverage is
missing. The reserved reviewer performs no commands during authoring. Structural
verification is not an external auditor opinion or professional acceptance.

Run in a new private destination, using a Python environment with the project
dependencies and `PYTHONPATH=src:.`:

```bash
python -m enterprise.audit_suite.fresh_identity_family_procedure run \
  --repository /absolute/path/to/implementation-checkout \
  --private-repository /absolute/path/to/authorized-private-sources \
  --destination /absolute/path/to/new-private-run
python -m enterprise.audit_suite.fresh_identity_family_procedure verify \
  --destination /absolute/path/to/new-private-run
python -m pytest -q tests/audit_suite/test_fresh_identity_family_procedure.py
```

Verification independently checks immutable trigger definitions, pinned original
business bytes and inherited journal rows, exact native member vectors at both
clocks, original collection custody and revoked grants, command hash chains and
actor separation, unchanged authored methods, recomputed control observations,
every population/selection/sample item and exact workpaper/inspection bytes.
Output directories are 0700 and files 0600. Failed and provisional runs are
preserved; the verifier never repairs or reseals them.
